Animation centrale du CM : agent à gauche, environnement TinyWorld à droite. 1. environnement fournit observation ; 2. agent choisit action ; 3. environnement évolue ; 4. reward revient ; 5. boucle. Faire tourner plusieurs fois.

Vocabulaire

Policy \(\pi\)

Une policy

\[ \pi(a|s) \]


répond à :

Dans cet état, quelle action choisir ?

La récompense totale

L’objectif n’est pas forcément

maximiser le prochain reward.

Mais plutôt :

maximiser les récompenses futures.

Return

\[ G_t=r_{t+1}+\gamma r_{t+2}+\gamma^2r_{t+3}+\cdots \]

\(\gamma\) : discount factor

C’est là que le RL devient intéressant

Une action

peut influencer

des récompenses

très loin dans le futur.

Le reward est votre interface

Vous ne programmez pas directement :

if predator:
    run_away()

Vous programmez plutôt :

death = -100
survival = +1
food = +10

Reward shaping

Ajouter des signaux intermédiaires :

+10 manger
+2 se rapprocher de nourriture
-2 se rapprocher du prédateur
-100 mourir

Mais attention

L’agent optimise

ce que vous mesurez.

Pas ce que vous vouliez dire.

Reward hacking

Vous donnez :

+1 chaque fois que l'agent touche une ressource


L’agent découvre peut-être :

une boucle permettant de la toucher sans jamais la consommer.

[ILLUSTRATION] Reward hacking

Petit exemple humoristique TinyWorld : objectif humain “collecter efficacement”, mais agent tourne en boucle autour d’une mécanique donnant artificiellement des points.

BLOC 3

Apprendre la valeur

Une idée simple

Dans un état donné :

UP      ?
DOWN    ?
LEFT    ?
RIGHT   ?


Attribuons une valeur

à chaque action.

Q-value

\[ Q(s,a) \]

représente :

la récompense future attendue

si l’on choisit

l’action \(a\)

dans

l’état \(s\).

Bellman

\[ Q(s,a) \approx r+\gamma\max_{a'}Q(s',a') \]

valeur actuelle

=

récompense immédiate

meilleur futur estimé

[ANIMATION] Bellman dans une grille

Agent dans une petite grille. Une action RIGHT donne reward immédiat puis mène à une nouvelle case. Afficher les Q-values du nouvel état et propager la meilleure valeur vers l’état précédent. Animation intuitive, pas démonstration formelle.

Q-learning

On observe une transition :

(s, a, r, s')

et on rapproche

\[ Q(s,a) \]

de

\[ r+\gamma\max_{a'}Q(s',a'). \]

Mais…

Une image 64×64 ?

Une grille complexe ?

Des centaines de variables ?


Impossible de stocker tous les états possibles.

Deep Q-Network

\[ Q_\theta(s,a) \]

Un réseau de neurones reçoit l’état

et prédit une valeur pour chaque action.

Pipeline DQN

Observation
     ↓
   Réseau
     ↓
Q(UP) Q(DOWN) Q(LEFT) Q(RIGHT)
     ↓
   Action

L’entraînement

Transition observée :

(s, a, r, s')

Prédiction :

\[ Q_\theta(s,a) \]

Cible :

\[ y=r+\gamma\max_{a'}Q(s',a') \]

Une loss

\[ L= \left( Q_\theta(s,a)-y \right)^2 \]


Et nous savons déjà minimiser une loss.

[ANIMATION] DQN complet

Boucle : observation → réseau → Q-values → action → environnement → reward + nouvel état → target → loss → backward → réseau. Faire apparaître les éléments progressivement.

Mais les données arrivent dans l’ordre

s₀
s₁
s₂
s₃
s₄
...

Elles sont fortement corrélées.

Replay Buffer

On stocke les transitions :

(s, a, r, s')

dans une mémoire.

Puis on tire :

des mini-batches aléatoires.

[ILLUSTRATION] Replay buffer

Agent → flux de transitions → buffer représenté comme une mémoire → échantillonnage aléatoire de plusieurs transitions → réseau.

Target Network
